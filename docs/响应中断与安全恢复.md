# 响应中断与安全恢复

## 发送语义

每个 job 在首次可能发出 POST 前创建独占 submission marker（`O_EXCL`）。marker 已存在时，程序不会再次创建 POST。发送进程只做一次生成 POST；`-1`、SSL EOF、timeout、IncompleteRead、5xx 和 429 都不会触发生成重试。网络调用开始后但响应未完整确认时，验收状态是 `unknown`。未建立网络调用的本地配置/输入错误才是 `not_sent`。

`gen.call(fields, files, ...)` 仍返回 `(status, text)`；新的 `call_structured` 额外返回结构化报告，包含 `phase`、`classification`、HTTP 状态、响应类型、声明/实际字节数、提交次数、固定 `retryable_generation=false` 和耗时。公开报告和 ledger 不保存密钥、token、签名 URL 或原始服务端错误。

## 结果保存

b64 和 URL 结果都先写 job 临时文件，完整加载 Pillow 后再原子发布。输出已存在时不会截断或覆盖；失败时保留旧文件。完整 200 响应保存为私有 snapshot，URL 结果另外保存为私有本地 pending 记录，供本机恢复使用。

## 恢复

`run_round.py --recover-from SNAPSHOT --out OUT` 或 `zimage.py edit --recover-from JOB_DIR --out OUT` 只读取本地完整 snapshot，或者对其中的 URL 做 GET（最多 3 次、总预算 300 秒），再继续外层图片验收。恢复入口绝不 POST；没有可用 URL 或完整 snapshot 时记录 `cannot_recover_unknown`。GET 下载失败不会增加生成 POST 计数。

恢复不解决跨 job 并发锁问题，也不把语义验收（如整图 `NEEDS_REVIEW`）误报成 PASS。dry-run 和 cache hit 的 `submit_attempts` 为 0。
