# 改图（ZCode 原生，AI 主流程）

AI 默认负责理解自然语言、分配输入图角色、编译或调用提示词、运行预检、提交 CLI、验收结果并登记经验。网页有涂遮罩、画廊和无限画布（`zimage.py board`）；画布可写提示词并生成，但仍走现有 `edit` / `run_round`（一次 POST、指纹、环境变量凭据）。DSH 不属于默认运行路径。

跨图任务先明确：哪张是目标/身份图，哪张是动作、构图或风格参考；身份图只提供主人公特征，参考图不得把自己的角色、服饰或道具泄漏进结果。复杂多图任务可由只读分析子代理审查角色和提示词，但真实提交只能由主 AI 流程发起。

## 何时用

- 用户给一张图，要**改其中一块**（换背景、重画道具、修手、去某物）。
- 用户给一张图，要**整体改画风 / 改色调**（整图档位）。
- 用户要做**确定性处理**：线稿调淡、放大、裁成某比例、拼版对照、量调子——这些**不该调接口**。
- 用户要看**图库**里的成果／候选／输入。
- 用户要把多张图摊在**无限画布**上对照、加字、再生成（即梦式）→ `zimage.py board`。

## 不适用（别硬上）

- **风格提取／蒸馏成提示词、定点姿态迁移、提示词怎么写** → 用 `style-distill` 技能，
  那里有七条铁律、四问、负向两层与失败态词库。本技能只管**机械链路**，不重复那套规范。
- 需求能写成"对现有像素做某个确定变换"（调浓淡／放大／裁切／拼版／加纸纹／改色调）
  → **走 `local`，不要调接口**。生成必然重掷脸、姿态、构图，做不到"其他都不用动"。

## 命令速查

所有命令都从工作区根目录跑，用 `C:\Python314\python.exe zcode-image-edit\bin\zimage.py <子命令>`。

| 子命令 | 用途 |
|---|---|
| `doctor` | 自检：依赖／凭据有无／脚本就位／ZCode 存储／技能安装状态。**不调接口**，排查第一步 |
| `edit` | 改图主命令：区域→遮罩→调接口→落盘 |
| `local` | 确定性本地操作，转发 `round_lib/local_ops.py`（不调接口） |
| `serve` | 拉起网页手涂页并打开浏览器 |
| `board` | 拉起无限画布（放图、加字、写提示词、生成贴回；走现有 edit） |
| `gallery` | 拉起画廊页并打开浏览器 |
| `stop` | 停掉上面拉起的本地服务 |

### 区域规格（二选一或混用，取并集）

```
--rect x0,y0,x1,y1        矩形（可重复）
--polygon "x,y x,y x,y"   多边形
--flood x,y[,tol]         种子点漫水——"把这片背景换掉"最趁手（默认 tol 30）
--grabcut                 前景分割；可选带初始框（对插画不稳，失败就退回漫水/多边形）
--mask-file M.png         用现成遮罩（alpha=255 即圈中区域）
--dilate N                区域外扩 N 像素，吃住抗锯齿边
--whole                   整图改图，不给区域
```

## 标准流程（顺序别跳）

1. **`doctor`** —— 先确认凭据与脚本就位。缺 `RELAY_API_KEY` 时 `edit` 会直接停下。
2. **生成本地计划** —— 复杂、多图、局部或高成本任务先用 `plan --plan-out PATH`；它只做预检、预算、指纹和遮罩准备，不发送上游。计划默认不可静默覆盖。
3. **圈区域** —— 挑上面的区域规格。**先报面积**：`edit` 会打印源图坐标下的区域占比，
   以及归一化到目标尺寸后的"可改面积"。
3. **`--dry-run`** —— 出预算报表（投喂 MiB／是否触发压缩／预计结果体积／取回时间三档），
   **不发送**。给区域时同时落盘遮罩。
4. **看涂红图** —— `run_round` 会把"模型实际收到的 image[1]"落盘成 `<out>.redmark.png`。
   **发送前必须看一眼红色落在哪一块**——落错位置等于白跑一次调用（实测踩过）。
5. **真跑** —— 去掉 `--dry-run`，或用 `edit --plan-file PATH` 复用已核验计划；执行前会检查源图、参考图、提示词、遮罩和 fingerprint 未变化。正向改图默认自带 `--mask-primary`（原因见下）。
6. **结果体检** —— 命令末会报结果尺寸与字节并**完整解码校验**；要调子/彩度就再跑
   `local tone-report`，别靠肉眼。

## 两种语义，别选错

- **正向（默认）**：圈中的区域**被修改**，其余像素物理不动。适合"只改这一小块"。
  **必须走 `--mask-primary`**：实测不加它时，模型会照抄一起发过去的干净原图把那块"恢复"，
  返回近乎原图（6 次调用全是如此，蒙版内最大改动仅 41–59）。
  代价：整图会被轻微微调（均值约 5/255），不是逐像素保护；
  只在你要"证明保护区逐像素没动"时才用 `--no-primary`。
- **反向（`--protect`）**：圈中的区域**被保护**，其余整张重建。适合"保住脸/身份，只重画服装或背景"。
  注意可改面积通常 >80%，等于整图重绘，**不适合"只改一小块"**。

机制：这套接口的 `mask` 字段**被静默忽略**，真正起作用的把要改的区域**硬涂成纯红**合成进
`image[1]`，并在提示词里声明"红色只是标记"。所以硬涂会**把该区原有信息整块抹掉**，
只适合"这块本来就要清掉重画"。

**那段"红色只是标记"的说明由工具自动前置**（`run_round.py` 会拼上 `SCHEMA_PROMPT`），
你的 `--prompt` **只写"这块要改成什么"即可**，不必自己重复声明红色约定。

⚠️ **这条曾经是坏的，且症状极具欺骗性**（2026-09-25 实测）：此前 `run_round.py` 从不前置这段说明
（而 `gen.py` 会），于是模型看到一块红色、只收到"改成平滑渐变"，就**把整张图重画了**——
接口照样回 HTTP 200，但保护区平均差异 20.71/255、只有 29% 保持原样，**比可改区动得还多**。
修好后同一配置：保护区 1.49/255、99.8% 保持原样。
**教训：只看 HTTP 200 会误判成功；改完一定要出数对比保护区的差异。**

## 尺寸与体积（实测，跑 ≥2K 前必看）

| 项 | 实测 |
|---|---|
| 投喂上限 | **1.96 MiB 通过 / 2.12 MiB 起被拒**（`400 form field too large`） |
| 尺寸白名单 | low=`1024x1536/1024x1024/1536x1024`；medium=`1152x2048/2048x2048/2048x1152`；high=`2160x3840/2880x2880/3840x2160`。**跨档组合会被上游拒** |
| 投喂体积由谁决定 | 由**目标尺寸**决定，与源图分辨率无关 |
| 最大杠杆 | **JPEG 投喂比 PNG 小约 5 倍**（`--encode jpg`）；"喂前本地降熵"几乎无效 |
| 输出体积→取回时间 | 1K≈2MB ｜ 2K≈4MB ｜ 4K≈10MB；CDN 实测 **0.2–97 KB/s**，抖动约 200 倍 |
| 中间稿 | **一律 1K**；"要更大"优先 `local upscale`，别为放大再跑一次生成 |

局部改图路径**不走压缩梯子**（它发的是涂红图，不是两张全尺寸图），超 1.96 MiB 会被**直接拒发**。

## 手涂遮罩（网页仍保留）

ZCode 里没有涂抹画布，但**网页本身是独立的 Python 服务**，与 DSH 无关：

```
python zcode-image-edit\bin\zimage.py serve      # 起服务并打开浏览器
# 涂完保存遮罩 → 再喂给 --mask-file
python zcode-image-edit\bin\zimage.py edit --image 原图.png --mask-file 涂的.png --prompt "..." --out 结果.png
python zcode-image-edit\bin\zimage.py stop
```

凭据已从环境变量注入服务端默认值，**页面上不必再手填 key**（但页面里的手填值只存浏览器
localStorage，服务端从不下发）。**环境变量里的 key 绝不会出现在渲染出的页面里**（已实测断言）。

## 画廊与「输入」页签

- `gallery` 打开画廊页（八个分类页签 + 页内灯箱）。
- 「输入」页签的数据源在 ZCode 侧要换：DSH 读会话日志，ZCode 把上传的图存成
  **base64 data URL 的 artifact 文本文件**、元数据在 SQLite。重跑：

```
python zcode-image-edit\zcode_inputs.py            # 生成 user_inputs_zcode.json
# 让画廊用它（而不是 DSH 版索引）：
set GALLERY_USER_INPUTS=<工作区>\style-distill\round_lib\user_inputs_zcode.json
python zcode-image-edit\bin\zimage.py gallery
```

**报 0 条是正常的**：这台机器上 ZCode 的 `payload.attachments` 全是空数组（实测：本项目 12 行
`sendText` 全空、artifacts 里 94 个文件全是工具结果）。在 ZCode 对话里真发一张图后重跑即可看到。

## 纪律（违反会被用户纠正）

1. **命令一律写成脚本文件，不内联**；脚本内部也**禁止用 ASCII 直引号包中文**（一律「」）。
2. **新增或修改任何 `.py`，执行前先 `compile()`**；写回后再全量复核一次。
3. **能出数的就不要靠肉眼**——面积用 %、体积用 MiB、结果用完整解码校验、本地操作用逐字节比对。
4. **凭据只从环境变量读**（`RELAY_API_KEY` / `RELAY_BASE_URL` / `RELAY_MODEL`），
   **不写入任何文件、不进仓库**。
5. 报结论要标依据：**【实测】／【文件核实】／【判断】／【未验证】**。

## 已知缺口（如实标注）

- **上游有内容审核**（2026-09-25 换到 `api-slb.micuapi.ai` 后实测）：`400 moderation_blocked
  "内容被安全审核拦截 (疑似成人内容)"`。**实测一张穿白色吊带的人物图被直接拦下**，而纯背景图层顺利通过。
  旧上游没有这道闸，所以历史配方里从未考虑过它。→ 人像素材要有被拦的准备，
  必要时换素材、改提示词、或换上游。
- 【实测】结果尺寸可能不等于请求：走 `b64` 路线时请求 1024×1536 回了 848×1264（≈源图）。
  别对像素级尺寸做假设，落盘后按实际尺寸核对。
- 【未验证】`--grabcut` 对动漫插画的效果未做过对照，可能不如 `--flood` 稳。
- 【未验证】画廊「输入」页签在 ZCode 侧的端到端表现：脚本结构已按实测的存储事实写好，
  但**本机还没有任何 ZCode 上传的图**，所以只能验到"如实报 0"。
- 【判断】纯文本给不出小结构（手、细链、小饰品）的保真度天花板——那类失败要升级到
  局部重绘或换通道，见 `style-distill` 的升级规则。
